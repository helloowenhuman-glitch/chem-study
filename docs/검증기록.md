# 구현 및 검증 기록

계획: 구현계획.docx

- 승인된 시안과 웹사이트 후 WebView APK 순서를 따랐습니다.
- 원래 작업 폴더에는 앱 소스와 Git 저장소가 없어 web-app에 독립적으로 구현했습니다.
- 사용자님의 실행 시간 절약 지침에 따라 패키지 설치가 없는 웹 구성을 선택했고 APK 빌드는 실행하지 않았습니다.
- 핵심 테스트 7개의 실패를 먼저 확인한 뒤 구현하고 통과를 확인했습니다.
- 실제 원격 자료에서 10회차와 DT 9회차의 60문항 및 exam의 개념 일치 문항을 확인했습니다.
- 모바일 360px에서 로그인 창과 실제 문항 로딩 및 서버 채점과 해설을 확인했습니다.
- 독립 검토 1회에서 계정 변경 중 지연 응답과 exam 개념 별칭 손실을 찾았습니다. 두 재현 테스트가 실패하는 것을 확인하고 수정했습니다. 총 9개 테스트가 통과했습니다.
- 사용자님께서 Supabase SQL의 Success 결과를 확인하셨고, 세 테이블의 비로그인 접근 차단을 확인했습니다. 실제 두 계정 간 RLS 검증은 아직 하지 않았습니다.
- 기존 DT 리포트 API 주소는 정상 JSON 응답을 받지 못해 실제 학생 리포트 연동 완료로 표시하지 않았습니다.
- 로그인 세션 영구 저장과 자동 갱신을 명시하고, WebView의 일시 중지와 재개 및 쿠키 저장 처리를 추가했습니다. 연결을 저장한 뒤 새 요청에서 복원하는 검증을 포함해 핵심 테스트 10개가 통과했습니다.
- JDK 21과 Android SDK 35로 Java 컴파일을 확인했습니다. APK 빌드와 설치 및 실제 앱 종료 후 복원은 아직 실행하지 않았습니다.

## 다중 회차 시험 대비

- 사용자님께서 이후 APK 빌드의 BUILD SUCCESSFUL 결과를 전달하셨으며, APK를 카카오톡 전송용 ZIP으로 압축했습니다. 실제 휴대폰 설치와 종료 후 복원 결과는 아직 전달받지 못했습니다.
- 1·2·3회차처럼 여러 회차를 선택하여 도입 개념의 합집합으로 출제하도록 변경했습니다. 1·3회차만 선택하면 2회차 개념을 제외합니다. 같은 지문과 선택지는 중복 출제하지 않습니다.
- 개념별로 균등하게 배분하고 나머지와 부족한 개념의 몫을 다른 개념에 배정합니다. 공유 exam 문항은 개념 슬롯을 재배정하여 중복 없이 사용하며, 준비 경로에서는 시험지 4개 제한 때문에 개념이 누락되지 않도록 했습니다.
- 새 기능 테스트의 실패를 먼저 확인한 뒤 구현했습니다. 독립 검토에서 공유 문항의 첫 개념 편중과 시험지 조회 제한을 발견하여 재현 테스트를 추가하고 수정했습니다. 후속 검토에서 남은 중요 문제는 발견하지 못했습니다. 핵심 테스트 16개와 문법 검사가 통과했습니다.
- 실제 1·2·3회차 자료는 중복 제거 후 DT 150문항, exam 18문항입니다. exam에서 연결된 4개 개념의 가용 문항 수 1·6·7·4를 기준으로 10문항이 1·3·3·3으로 배분되는 것을 확인했습니다. 정답과 해설은 출제 응답에 포함하지 않습니다.
- 360px 브라우저에서 다중 선택, 선택 전체 해제 시 시작 비활성화, 새로고침 후 선택 복원, 실제 DT 10문항 풀이 진입과 가로 넘침이 없는 것을 확인했습니다. 계정별 회차 선택은 기기 저장소에 기억하며 기기 간 회차 조합 동기화는 제공하지 않습니다.
- SQL과 APK 변경은 없습니다. 이번 웹 변경의 운영 반영은 GitHub 푸시 후 Vercel 자동 배포가 필요합니다.

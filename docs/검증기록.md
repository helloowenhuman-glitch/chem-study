# 구현 및 검증 기록

계획: 구현계획.docx

- 승인된 시안과 웹사이트 후 WebView APK 순서를 따랐습니다.
- 원래 작업 폴더에는 앱 소스와 Git 저장소가 없어 web-app에 독립적으로 구현했습니다.
- 사용자님의 실행 시간 절약 지침에 따라 패키지 설치가 없는 웹 구성을 선택했고 APK 빌드는 실행하지 않았습니다.
- 핵심 테스트 7개의 실패를 먼저 확인한 뒤 구현하고 통과를 확인했습니다.
- 실제 원격 자료에서 10회차와 DT 9회차의 60문항 및 exam의 개념 일치 문항을 확인했습니다.
- 모바일 360px에서 로그인 창과 실제 문항 로딩 및 서버 채점과 해설을 확인했습니다.
- 독립 검토 1회에서 계정 변경 중 지연 응답과 exam 개념 별칭 손실을 찾았습니다. 두 재현 테스트가 실패하는 것을 확인하고 수정했습니다. 총 9개 테스트가 통과했습니다.
- 사용자님께서 Supabase SQL의 Success 결과를 확인하셨고, 세 테이블의 비로그인 접근 차단을 확인했습니다. 실제 두 계정 간 RLS 검증은 아직 하지 않았습니다.
- 기존 DT 리포트 API 주소는 정상 JSON 응답을 받지 못해 실제 학생 리포트 연동 완료로 표시하지 않았습니다.
- 로그인 세션 영구 저장과 자동 갱신을 명시하고, WebView의 일시 중지와 재개 및 쿠키 저장 처리를 추가했습니다. 연결을 저장한 뒤 새 요청에서 복원하는 검증을 포함해 핵심 테스트 10개가 통과했습니다.
- JDK 21과 Android SDK 35로 Java 컴파일을 확인했습니다. APK 빌드와 설치 및 실제 앱 종료 후 복원은 아직 실행하지 않았습니다.

## 다중 회차 시험 대비

- 사용자님께서 이후 APK 빌드의 BUILD SUCCESSFUL 결과를 전달하셨으며, APK를 카카오톡 전송용 ZIP으로 압축했습니다. 실제 휴대폰 설치와 종료 후 복원 결과는 아직 전달받지 못했습니다.
- 1·2·3회차처럼 여러 회차를 선택하여 도입 개념의 합집합으로 출제하도록 변경했습니다. 1·3회차만 선택하면 2회차 개념을 제외합니다. 같은 지문과 선택지는 중복 출제하지 않습니다.
- 개념별로 균등하게 배분하고 나머지와 부족한 개념의 몫을 다른 개념에 배정합니다. 공유 exam 문항은 개념 슬롯을 재배정하여 중복 없이 사용하며, 준비 경로에서는 시험지 4개 제한 때문에 개념이 누락되지 않도록 했습니다.
- 새 기능 테스트의 실패를 먼저 확인한 뒤 구현했습니다. 독립 검토에서 공유 문항의 첫 개념 편중과 시험지 조회 제한을 발견하여 재현 테스트를 추가하고 수정했습니다. 후속 검토에서 남은 중요 문제는 발견하지 못했습니다. 핵심 테스트 16개와 문법 검사가 통과했습니다.
- 실제 1·2·3회차 자료는 중복 제거 후 DT 150문항, exam 18문항입니다. exam에서 연결된 4개 개념의 가용 문항 수 1·6·7·4를 기준으로 10문항이 1·3·3·3으로 배분되는 것을 확인했습니다. 정답과 해설은 출제 응답에 포함하지 않습니다.
- 360px 브라우저에서 다중 선택, 선택 전체 해제 시 시작 비활성화, 새로고침 후 선택 복원, 실제 DT 10문항 풀이 진입과 가로 넘침이 없는 것을 확인했습니다. 계정별 회차 선택은 기기 저장소에 기억하며 기기 간 회차 조합 동기화는 제공하지 않습니다.
- SQL과 APK 변경은 없습니다. 이번 웹 변경의 운영 반영은 GitHub 푸시 후 Vercel 자동 배포가 필요합니다.

## 회차별 개념과 공식 및 오답 해설

- 사용자님께서 승인하신 구성으로 개념·공식 안내와 풀이 결과의 오답 상세 및 오답만 재풀이를 추가했습니다. 구현 계획은 study-guide-plan.docx에 기록했습니다.
- 공식 회차표의 211개 개념을 10회차와 27개 주제로 연결합니다. 핵심 원리, 공식과 기호·단위, 적용 조건, 접근 순서, 별도 학습 예시와 주의점, 원문 강의 출처를 제공합니다. 실제 원격 plan과 전체 연결 개수를 확인했습니다.
- 결과에는 오답의 실제 지문과 선택지 및 내 답과 정답을 함께 표시합니다. 원문 해설과 선택지별 오개념을 보존하고, 출제 전 응답에서는 learningPoint와 misconception(s)을 포함한 비공개 필드를 제거합니다. 계산용 일반 안내 및 별도 예시를 현재 문항의 실제 계산과 구분합니다.
- 새 테스트 실패 후 구현했습니다. 총 21개 핵심 테스트와 14개 JavaScript 모듈의 문법 검사가 통과했습니다. 실제 exam 문항을 오답 제출하여 원문 선택지별 오류 설명과 응답 문구의 일치, 관련 주제 연결을 확인했습니다.
- 독립 검토와 실제 UI에서 결과 렌더링의 누락 import 오류를 재현하여 수정했습니다. 숫자 OX 문항의 명시적 나눗셈 해설도 계산 안내로 이어지도록 보완했습니다. 후속 독립 검토에서 남은 중요 문제는 발견하지 못했습니다.
- 360px 화면에서 개념·공식 열람, 실제 DT 5문항 풀이, 오답 2개 상세 표시, 그 2문제만 재풀이, 재풀이 2/2 정답 결과를 확인했습니다. 가로 넘침은 없었습니다. 로그인된 사용자 기기의 실제 재풀이 기록 저장은 이번 UI 확인 범위에 포함하지 않았습니다.
- 현재 세션의 상세 결과는 새로고침하면 초기화됩니다. 기존 계정의 학습 기록 저장과 리포트 연결은 유지합니다. 새 SQL과 APK 빌드는 필요하지 않습니다. 운영 사이트 반영은 사용자님의 GitHub 푸시 후 Vercel 자동 배포가 필요합니다.

## 별표와 즉시 채점

- 맞은 문제를 포함한 별표 표시와 해제, 오답·별표 통합 결과와 재풀이, 별표 목록 및 문제 다시 불러오기를 구현했습니다. 별표는 문제 번호·개념·회차만 기기 및 계정에 저장합니다. 계정 저장에는 bookmarks.sql의 추가 실행이 필요하며 새 프로젝트 schema.sql에도 포함했습니다.
- instant 옵션에만 선택한 묶음의 정답과 해설을 제공하며, 동일 주제 안내는 한 번만 전송합니다. 기본 API는 이전 방식과 호환됩니다. 서버는 기록을 저장할 때 여전히 원문으로 재검증합니다.
- 답안과 별표 변경을 기기에서 계정별로 임시 보관하고 온라인 복귀·재실행·수동 요청에 동기화합니다. 최신 별표 변경을 오래된 성공 응답이 지우지 않도록 버전을 확인합니다. 저장 실패 시 후속 답안을 먼저 저장하지 않고, 같은 동기화의 완료를 기다린 뒤 학습 기록을 읽습니다.
- 핵심 테스트에 즉시 채점 정보, 주제 중복 전송 방지, 정답 별표와 오답 합집합, 계정별 임시 저장, 오래된 성공 응답, 소유자 기준 별표 저장·해제, 답안 저장 순서 및 동기화 완료 대기를 추가했습니다. 독립 검토에서 저장 순서와 완료 대기 문제를 발견하고 실패 재현 후 수정했습니다. 후속 검토에서 남은 중요 문제는 발견하지 못했습니다.
- 360px 브라우저에서 문제 묶음을 로드한 뒤 개발용 네트워크를 오프라인으로 바꾸어 별표와 채점을 실행했습니다. 정답과 해설이 표시되었고 해당 동작의 네트워크 추가 요청은 0건이었습니다. 오프라인 5문항 완료 후 정답 별표 1개와 오답 1개가 함께 표시됐습니다. 네트워크 설정을 복구하고 새로고침한 뒤 별표 1개 복원 및 해당 문제 다시 불러오기를 확인했습니다.
- 실제 Supabase 별표 테이블 적용과 인증된 기기에서의 계정 간 동기화는 아직 확인하지 않았습니다. 브라우저 개발용 오프라인 설정은 검사 직후 원복했습니다. APK 변경은 없습니다.
